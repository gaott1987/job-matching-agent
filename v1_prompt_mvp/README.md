# V1.0: Prompt 驱动的 MVP 阶段

## 🎯 阶段目标
在进入复杂的 Workflow 开发前，先用最轻量的大模型客户端（豆包）验证：
1. 复杂的逻辑推理（岗位画像、算分、简历建议）能否通过单次超级 Prompt 完成？
2. 不同模型架构对长文本+图片的理解能力差异。

## 🧪 基准测试 (Benchmark)

我们使用虚构的“张三”档案与模拟 JD 截图，在豆包上进行了 3 组测试：

| 测试环境 | 核心能力 | 执行结果表现 | 架构启示 |
| :--- | :--- | :--- | :--- |
| 工作模式 | 具备 Agent 规划与工具调用 | 结果最全面，但存在过度拆解与冗余 | 证明在**静态单次任务**中，Agent 的自主规划反而带来噪音；当前阶段应以单次强推理为主 |
| **对话专家模式** | **强视觉 + 强推理 (单次上下文)** | **逻辑连贯，完美输出报告** | **确立为 V2 阶段的核心基线** |
| 对话快速模式 | 轻量模型 | 无法识别 JD 截图，流程失败 | 证明复杂任务必须使用强模型 (Vision+Pro) |

## 🧠 Prompt 工程解析
本阶段的核心资产是 `prompts/super_prompt_v1.md`。
- **思维链 (CoT)**：强制模型先解析 JD 和岗位池，再算分，最后给建议，避免直接瞎编。
- **反幻觉约束**：要求简历建议必须严格引用档案原话。

## 🚧 V1 的局限与痛点
虽然“对话专家模式”跑出了完美的报告，但面临致命痛点：
1. **无法自动化**：每次都要手动上传三个文件、粘贴长 Prompt。
2. **无法批量处理**：面对海量 JD 时效率极低。
3. **格式不稳定**：有时会附带废话，无法保证纯 JSON 或固定结构的 Markdown 输出。

💡 **演进方向**：构建自动化 Workflow 来解决上述问题。
